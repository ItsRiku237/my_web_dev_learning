# 2. console.log()

## Server Component

```jsx
console.log("Hello Server")
```

Shows in

```
✅ VS Code Terminal

or

Deployment Logs (Vercel)
```

Never appears in browser.

---

## Client Component

```jsx
"use client"

console.log("Hello Client")
```

Shows in

```
✅ Browser Developer Console
```

---

## Remember

| Code | Shows Where |
|-------|-------------|
| Server Component | Terminal |
| Client Component | Browser |
| API Route | Terminal |
| Server Action | Terminal |
| Button Click | Browser |

# 5. Common Mistakes

❌ Using useState without

```jsx
"use client"
```

---

❌ Using fs in Client Component

---

❌ Using localStorage in Server Component

---

❌ Putting every component in Client

---

❌ Exposing secret API keys

---

# 6. Best Practices

✅ Keep pages Server Components.

✅ Make only interactive parts Client Components.

✅ Fetch data on server.

✅ Use fs/database only on server.

✅ Use useState only in client.

✅ Keep JavaScript bundle small.

# 7. Interview Questions

### Is every component Client?

❌ No

Default is Server.

---

### How to create Client Component?

```jsx
"use client"
```

---

### Can Server import Client?

✅ Yes

---

### Can Client import Server?

❌ No (generally avoid)

---

### Where does useState work?

✅ Client

---

### Where does fs work?

✅ Server

---

### Where does console.log() appear?

Server

```
Terminal
```

Client

```
Browser
```

---

### Why are Server Components faster?

- Less JavaScript
- Better SEO
- Faster initial load
