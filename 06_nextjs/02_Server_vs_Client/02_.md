# 1. ⭐ Golden Rule

Before using anything in Next.js, ask yourself one question:

> **Does this feature need the Browser?**

If **YES**

➡️ Client Component

If **NO**

➡️ Server Component

---

Examples

Need button click?

```
Client
```

Need database?

```
Server
```

Need localStorage?

```
Client
```

Need file system?

```
Server
```

Need useState?

```
Client
```

Need API Fetch?

```
Usually Server
```

# 2. React Hooks

React Hooks are special functions.

Some require the browser.

Some don't.

---

## ✅ useState

Purpose

Store changing data.

Example

```jsx
const [count, setCount] = useState(0)
```

Need Browser?

✅ Yes

Works in

```
Client Component
```

Example

```jsx
"use client"

import { useState } from "react"

export default function Counter(){

    const [count,setCount]=useState(0)

    return(
        <>
            <h1>{count}</h1>

            <button
            onClick={()=>setCount(count+1)}
            >
            +
            </button>
        </>
    )
}
```

---

## ❌ Server?

No.

Because server doesn't keep changing state after sending HTML.

---

## useEffect

Purpose

Run code after page loads.

Example

```jsx
useEffect(()=>{
    console.log("Loaded")
},[])
```

Need Browser?

✅ Yes

Runs only

```
Client
```

---

Common Uses

- Fetch API after load
- Timer
- Event listeners
- localStorage
- document.title

---

## useRef

Purpose

Store reference.

Example

```jsx
const inputRef = useRef()
```

Need Browser?

Usually

✅ Yes

Example

```jsx
inputRef.current.focus()
```

Only browser has input element.

---

## useContext

Purpose

Share data.

Works

✅ Client

Usually.

---

## useReducer

Works

✅ Client

---

## useMemo

Works

✅ Client

Used for optimization.

---

## useCallback

Works

✅ Client

Used to memoize functions.

---

## useLayoutEffect

Works

✅ Client

Runs before browser paints.

---

## useTransition

Works

✅ Client

Used for smoother UI updates.

---

## useOptimistic

Mostly

✅ Client

Used in forms and optimistic UI.

# 8. Fetch API

Many beginners ask:

Can fetch be used on both?

Answer

YES.

---

Server

```jsx
export default async function Page(){

    const res=await fetch("https://api.example.com")

    const data=await res.json()

    return <h1>{data.name}</h1>
}
```

Runs

Before page reaches browser.

Better SEO.

---

Client

```jsx
"use client"

useEffect(()=>{

fetch("/api/users")

},[])
```

Runs

After page loads.

---

When should you use Server Fetch?

✅ SEO

✅ Blogs

✅ Products

✅ Dashboard

✅ Better Performance

---

When Client Fetch?

✅ Search

✅ Live Updates

✅ Auto Refresh

✅ Infinite Scroll

# 1. Server Actions

## What are Server Actions?

Server Actions allow you to execute server-side code **directly from a form or a client component** without creating an API route.

Before:

```
Client
   ↓
API Route
   ↓
Database
```

Now:

```
Client
   ↓
Server Action
   ↓
Database
```

---

Example

```jsx
// app/actions.js

"use server";

export async function addUser() {
    console.log("User Added");
}
```

Use it

```jsx
<form action={addUser}>
    <button>Add User</button>
</form>
```

Best for

- Login
- Register
- Contact Form
- CRUD Operations

---

# 2. Async Server Components

Server Components can be async.

Example

```jsx
export default async function Home() {

    const res = await fetch("https://dummyjson.com/products");

    const data = await res.json();

    return (
        <h1>{data.products.length}</h1>
    );
}
```

Why?

Because server can wait before sending HTML.

Client Components cannot directly be async components.

❌ Wrong

```jsx
"use client"

export default async function Home(){}
```

---

# 3. Passing Data Between Components

## Server ➜ Server

Works normally.

```jsx

```

---

## Server ➜ Client

Works.

Example

```jsx
<Navbar username="Riku"/>
```

Server fetches data.

Client displays it.

---

## Client ➜ Client

Normal React props.

```jsx
<Card name="Laptop"/>
```

---

## Client ➜ Server

❌ Cannot directly send props upward.

Need

- Form
- Server Action
- API

# 5. Serialization

When Server sends data to Client, the data must be serializable.

✅ Allowed

```jsx
String

Number

Boolean

Array

Object

null
```

Example

```jsx
<User
name="Riku"
age={20}
/>
```

---

❌ Not Allowed

```jsx
Function

Class Instance

Database Connection

File Handle
```

Wrong

```jsx
<ClientComp

myFunction={()=>{}}

/>
```

# 8. Interview Questions

## Why Server Components?

Answer

- Better Performance
- Better SEO
- Smaller JavaScript Bundle
- Faster Loading

---

## Why Client Components?

Need

- useState
- Events
- Forms
- Browser APIs

---

## Can Server Component import Client Component?

✅ Yes

Example

```jsx
export default function Home(){

    return(

        <>
            <NavbarClient/>
        </>

    )
}
```

---

## Can Client Component import Server Component?

❌ Generally No.

Server Components should stay above Client Components.

---

## Which one is default?

✅ Server Component

---

## Why use "use client"?

To tell Next.js

> "Run this component in the browser."

---

# 9. Best Practices

✅ Keep pages as Server Components.

✅ Make only interactive components Client Components.

✅ Fetch data on the Server whenever possible.

✅ Keep secret keys on the Server.

✅ Use Client Components only when needed.
